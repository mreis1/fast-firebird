# 2026-08-20 — Hardening the script client-commands plan

Marcio review of `plans/script-client-commands.md`: (1) even with
`clientCommands` set, commands that would corrupt the driver's transaction
must be PREVENTED, always; (2) drop `'send'` raw mode if it creates more
problems than it solves.

Both applied — and (2) is what makes (1) airtight:
- `clientCommands` is now `'process' | 'error'` only. `'send'`'s sole effect
  was reproducing the desync bug (server-executed COMMIT kills the wrapper
  tx under the executor); no correct program can depend on it, and it was
  the one configuration that could defeat the guard.
- New unconditional **wire guard** invariant: statements whose HEAD is
  transaction-control (COMMIT / ROLLBACK except `ROLLBACK TO …` /
  SET TRANSACTION) are never transmitted by executeScript — every path
  processes or rejects with a named error. Crucially this includes
  UNPARSEABLE `SET TRANSACTION` variants (RESERVING, READ CONSISTENCY,
  future syntax): head-match decides "ours, never wire"; detail parsing only
  decides process-vs-error. Safe-in-tx statements (SAVEPOINT / RELEASE /
  ROLLBACK TO) stay server-side; EXECUTE BLOCK is not a vector (PSQL has no
  COMMIT; autonomous txs are separate handles).
- Noted as separate future hardening (out of scope here): `db.run('COMMIT')`
  has the same desync property at the API level; `classifyClientCommand`
  could guard run() paths too.

Two decisions marked DECIDED in the plan; two still open (RECONNECT commits
dirty tx; perStatement COMMIT no-op). Phase 1 still awaiting go-ahead.

## Implementation session (same day) — phases 1+2 shipped

Go-ahead given (goal: implement the plan + a demo-app script zone). The two
open decisions implemented as chosen (RECONNECT commits a dirty tx like
isql's EXIT; perStatement COMMIT is a no-op success).

**`Attachment.reconnect()`** — the readonly constructor params
(wire/handshake/dbHandle) and `session` became private mutable fields behind
getters (transparent to all call sites — everything already read
`att.wire`/`att.session`/… as properties). `open()` split into a shared
`establish()`; `buildSession()` extracted so reconnect rebuilds the
StatementCache/InlineBlobCache and re-announces the inline-blob size on the
new wire. Attachment `generation` counter: Transaction and PreparedStatement
capture it at creation and refuse to run after a reconnect ("attachment was
reconnected — …"); lazy-blob `txAlive` gained the same check;
`PreparedStatement.close()` after reconnect is a silent no-op (the server
handle died with the old connection). `EventChannel.closeAll(reason?)` now
emits `'error'` per listener (try/catch — no error-listener must not crash
reconnect). `roundTrips` = base offset + current wire flushCount. A failed
re-establish leaves the attachment closed but retryable (options retained).

**Recognizer** — `classifyClientCommand` is TOTAL (never throws; malformed
input → null): head-match claims commit/rollback(-except-TO)/set transaction
/set autoddl/reconnect; details either parse or come back as
`{op:'unsupported', reason}` so the executor rejects by name — this is how
the wire guard composes with continueOnError. Grammar verified against
parse.y `tran_option`/`iso_mode`/`version_mode`: **bare READ COMMITTED = NO
record version** (plan table had rec_version — corrected), VERSION and
RECORD_VERSION both accepted, AUTO COMMIT → `autoCommit: true`, SNAPSHOT AT
NUMBER / RESTART REQUESTS / AUTO RELEASE TEMP BLOBID rejected by name.
`classifyStatement` widened to `'client'` (kind union — the documented
semver-minor note); `ROLLBACK [WORK] TO …` stays null/server-side.

**Executor** — `clientCommands: 'process' (default) | 'error'`; emitOk/
emitError helpers (every client command yields a StatementResult + fires
onProgress); perScript keeps a mutable wrapper tx + txOptions template +
dirty flag + autoDdl flag; RECONNECT commits (if unfinished) → reconnect →
reopen; SET TRANSACTION requires a clean tx, becomes the reopen template;
AUTODDL commits after each successful `kind==='ddl'` statement. perStatement:
SET TRANSACTION swaps options for subsequent statements, RECONNECT works,
rest no-op. 'none': SET TRANSACTION errors (defaultTransaction's job).
Caller-tx: everything errors, tx untouched.

**Demo app** — new Script runner panel (`ScriptPanel`) + POST
`/api/servers/:id/script` running on a DEDICATED attachment (a script
RECONNECT only re-attaches its own connection); per-statement trace via
onProgress so it survives a mid-script throw; 5 example scripts (checkpoints,
set transaction, reconnect via current_connection, autoddl, savepoints
staying server-side) + a client-commands reference table in a collapsible.
Verified live against fb5: reconnect example shows 2 distinct connection ids;
dirty SET TRANSACTION returns the named error with the full trace.
