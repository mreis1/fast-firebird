## Script client-commands plan (evening)
Marcio: the executor should PROCESS client commands (RECONNECT, COMMIT, …),
not ship them to the server. Plan written: `plans/script-client-commands.md`.
Key findings baked into it: COMMIT/ROLLBACK/SET TRANSACTION are IN the
server's DSQL grammar (parse.y tra_statement) — so today a script COMMIT
executes and desyncs the perScript wrapper transaction (latent bug →
process-by-default is a fix, with clientCommands: 'send' as the escape
hatch); RECONNECT exists in no Firebird grammar at all (IBExpert-ism).
Design: parser gains kind:'client' + ClientCommand on ParsedStatement
(ROLLBACK TO SAVEPOINT stays server-side); executor dispatch per mode
(checkpoints in perScript, no-ops in perStatement, errors on caller tx);
prerequisite Attachment.reconnect() (readonly→getter refactor, generation
guard invalidating pre-reconnect handles, cumulative roundTrips, pool-safe).
Absorbs parked B2 as script-driven SET AUTODDL. Awaiting go-ahead on the
four flagged decisions before phase 1.
